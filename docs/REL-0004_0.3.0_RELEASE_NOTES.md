# AI-Engineering 0.3.0 — Candidate Release Notes

**Status:** DRAFT / CANDIDATE PREPARATION / NOT PUBLISHED

These notes describe the intended `v0.3.0` release lineage selected by
REL-0004-02 and reconciled by REL-0004-02A. They do not create a tag, GitHub
Release, asset, or package-registry publication.

## Release scope

AI-Engineering 0.3.0 advances the verified v0.2.0 foundation with the completed
AUTO-0003 through AUTO-0022 work plus verified INFRA-0001 operational local-agent
integration.

### Project engineering workflows

- documentation ownership initialization and bounded documentation sync;
- python-engineering V2 bootstrap identity and explicit V1-to-V2 migration;
- project health/readiness inspection;
- deterministic reconciliation plan/apply workflows;
- restrictive reconciliation policy, explicit approval, bounded orchestration,
  and optional execution receipts.

### Read-only control and workstation operations

- bounded read-only GitHub/OpenCode control task classes: `status`, `inspect`,
  `plan`, `diff`, and exact-head `quality_verify`;
- local worker lifecycle supervision and portable workstation doctor behavior;
- exact post-merge Quality verification;
- reliability/observability hardening and no-replay stranded-claim
  terminalization;
- canonical project-state/document coherence through AUTO-0022.

### Public CLI corrections for 0.3.0

The established public routes remain behaviorally unchanged, while the parent
help hierarchy now explicitly exposes:

```text
ai-engineering project reconcile approve
ai-engineering project reconcile run
ai-engineering workstation doctor
```

Existing v0.2.0 routes remain available through the same `ai-engineering`
console script.

### MCP version alignment

Package metadata and the active MCP SDK initialize version are aligned to the
selected `0.3.0` version contract. Existing MCP tool names, schemas, and SAFE
execution boundaries are not expanded by this release-preparation change.

### INFRA-0001 local-agent integration

Verified INFRA-0001 is included in the 0.3.0 candidate lineage as
**operational/internal** scope. It adds repository-governed OpenCode/Ollama
roles, local-first routing, deterministic guards, shadow validation, and
workstation bootstrap/verification.

The importable modules `ai_engineering.local_agent_routing` and
`ai_engineering.local_agent_shadow` are additive operational implementation
surfaces. Their presence in the distribution does **not** establish a promise
of permanently stable public Python API.

The local-agent execution preference does not expand authority: no automatic
cloud fallback, protected-branch mutation, merge authority, credential
mutation, publication, or release authority is granted.

## Compatibility boundaries

- distribution name: `ai-engineering`;
- intended version: `0.3.0`;
- intended tag: `v0.3.0`;
- Python requirement remains `>=3.11`;
- runtime dependency remains `mcp>=1.27,<1.28`;
- console entry point remains `ai-engineering = ai_engineering.public_cli:main`;
- v0.2.0 project-create compatibility is preserved;
- default engineering bootstrap output intentionally advances from V1 to V2,
  with an explicit migration path for existing V1 projects.

No universal stability guarantee is made for post-v0.2.0 internal or
operational Python modules.
