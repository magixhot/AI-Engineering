# SDK-0001: Project Templates Framework (framework-level specification)

Note: `docs/SDK-0001_TEMPLATE_DESIGN.md` is the authoritative specification for SDK-0001 v1 (the
minimal standalone doc-first template). This document (`SDK-0001_PROJECT_TEMPLATES.md`) is a
framework-level reference and MUST NOT be interpreted as implying that all items listed here are
implemented in SDK-0001 v1. Where an item is out of scope for v1 it is explicitly placed under
"Future Scope" and marked as NOT IMPLEMENTED in SDK-0001 v1.

## Purpose

This document describes the Project Templates Framework at a high level and records the intended
behaviour, verification rules and non-normative future work. The authoritative, implementable
details for SDK-0001 version 1 are maintained in
`docs/SDK-0001_TEMPLATE_DESIGN.md`.

## SDK-0001 v1 (Authoritative scope)

SDK-0001 v1 implements a minimal standalone, documentation-first project template. The v1
generator produces only the doc-first skeleton and enforces the conventions described in
`SDK-0001_TEMPLATE_DESIGN.md`.

### Public creation API

The recommended SDK-0001 entry point is the typed Python API:

- `StandaloneProjectRequest` defines the target directory, required project name and description,
  optional project metadata, and optional additional documents.
- `create_standalone_project(request)` creates the standalone project.
- `StandaloneProject` returns the target directory, generated files, and the `main` default
  branch.

`ProjectTemplateGenerator` is the implementation layer for this API. The pre-existing
`create_project_template()` function remains available as a compatibility-level mapping-based API.
Neither public API expands v1 beyond the document-first template: v1 has no CLI, runtime or code
scaffold, generated `LICENSE`, or remote Git operations.

### Mandatory engineering documents (exact set for v1)

Every generated project in SDK-0001 v1 MUST include the following nine documents at project root:

- README.md
- AI_CHAT_START.md
- PROJECT_CONTEXT.md
- PROJECT_MAP.md
- CURRENT_STATUS.md
- ROADMAP.md
- DECISIONS.md
- CODING_STANDARDS.md
- MASTER_INDEX.md

These nine documents form the minimal required documentation baseline for any generated project
created by the v1 template.

### Required document metadata

Every required document MUST include metadata that states:

- its purpose;
- who maintains it;
- that it is created at project generation time;
- its mandatory sections; and
- content that is forbidden in that document.

The document-specific metadata requirements are authoritative in
`docs/SDK-0001_TEMPLATE_DESIGN.md`.

### Key v1 behaviours and constraints

- `docs/` directory: created only when additional, optional project-specific documents are
   provided to the generator. The generator MUST NOT create an empty `docs/` directory by default.
- `LICENSE`: recommended but NOT mandatory; v1 does not create or populate a license file by
   default (choice of license is a project-level decision).
- Default branch: for standalone generated projects the default branch is `main`.
- Placeholders supported by v1:
   - `{{PROJECT_NAME}}`
   - `{{PROJECT_DESCRIPTION}}`
   - `{{PROJECT_ID}}`
   - `{{AUTHOR}}`
   - `{{CREATED_DATE}}`
- Unresolved placeholders are NOT permitted in generated output: generation MUST fail if any
   placeholder remains unresolved in produced files.
- Placeholder syntax: v1 uses the placeholder naming and syntax defined in
   `docs/SDK-0001_TEMPLATE_DESIGN.md`. v1 DOES NOT support placeholder substitution in
   filenames.

## Verification and Git rules (v1)

- Target directory validation: target directory must be empty or non-existent before generation.
- Nested Git: the generator MUST refuse to initialize a repository if the target directory is
   inside an existing Git working tree (i.e. there is a `.git` entry in a parent directory).
- Git initialization: for standalone projects the generator initializes a new Git repository in
   the target directory and sets the default branch to `main` (with fallback for older Git).
- Initial commit: the generator makes an initial commit that includes only the files created by
   the generator (the nine required documents and any provided files under `docs/`). The commit
   message format is:

```
Initial project scaffold: <project-name> (Standalone template)
```

## Future Scope (NOT IMPLEMENTED in SDK-0001 v1)

The following items are explicitly OUT OF SCOPE for SDK-0001 v1 and are recorded here as
future work. They should not be assumed to be generated by the v1 template; consider these
features for a subsequent version and place them on the roadmap:

- `pyproject.toml` generation and population of build metadata
- `src/` package skeleton and runtime scaffolding
- `tests/` skeleton for unit/integration tests
- `.gitignore` creation
- Automated license selection and `LICENSE` file generation
- Placeholder substitution in filenames
- Advanced template types that produce code, CLI tools, or runtime implementations
- Automatic remote configuration or upstream pushes

Items in this section are NOT IMPLEMENTED in v1 and must be agreed and scoped before being
implemented in a future SDK-0001.x release.

## SDK-0001.1 Optional Python Scaffold

SDK-0001.1 implements the separately approved, opt-in Python scaffold described in
`docs/SDK-0001_1_PYTHON_SCAFFOLD_DESIGN.md`. It is enabled only through
`StandaloneProjectRequest.include_python_scaffold`, which defaults to `False` and therefore
preserves the V1 document-only output for existing callers.

When enabled, it adds the approved `pyproject.toml`, `.gitignore`, source package, and smoke
test to the V1 document baseline. It does not add a CLI, application logic, framework templates,
remote Git operations, dependency installation, or a generated `LICENSE`. The V1 exclusions
above remain historical V1 boundaries; they do not describe the separately scoped opt-in feature.
