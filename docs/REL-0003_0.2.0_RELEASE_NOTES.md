## What changed since 0.1.0

### Engineering Project Bootstrap

AUTO-0001 adds a bounded `python-engineering` bootstrap capability on top of SDK-0001.

The installed CLI exposes:

- `ai-engineering project bootstrap`

The bootstrap flow delegates project generation to the existing public SDK API and then performs fail-closed verification of required files, package structure, Git repository/root, `main` branch, initial commit, and smoke-test presence.

### Project Documentation Synchronization

AUTO-0002 adds deterministic local project inspection and bounded documentation synchronization.

The installed CLI exposes:

- `ai-engineering project docs check`
- `ai-engineering project docs plan`
- `ai-engineering project docs apply`

V1 writable scope remains exactly:

- `CURRENT_STATUS.md`
- `MASTER_INDEX.md`
- `PROJECT_MAP.md`

`check` and `plan` are read-only. `apply` uses SHA-256 original-content guards, preserves human-owned content outside managed sections, preserves LF/CRLF line-ending convention, and verifies written content after apply. Missing or malformed ownership markers remain manual-review conditions; V1 does not initialize markers automatically.

### Git/Python Execution Safety

SAFE-0002 extends the active MCP authority-root policy to Git and path-taking Python operations.

Key verified behavior includes:

- bounded MCP Git operations require `MCPConfig.workspace_root` itself to be the Git repository top level;
- parent-repository discovery above the configured root is rejected;
- Python syntax/package/test paths must resolve inside the configured root;
- traversal, outside-root paths, and supported link escapes are rejected before inspection/execution;
- authorized pytest execution uses the current interpreter, workspace-root cwd, `shell=False`, closed stdin, captured output, and a bounded timeout.

SAFE-0001 and SAFE-0002 are authorization/execution boundaries, not an operating-system sandbox.
